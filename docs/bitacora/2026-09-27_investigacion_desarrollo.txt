  código.

-----------------------------------------------------------------------------
5. RIESGOS DETECTADOS
-----------------------------------------------------------------------------
1. El servidor es la "fuente de verdad" del backend, no el repositorio.
   main.py, los modelos, connection.py y force_reset.py solo existen en el
   servidor ARM. Nadie puede revisarlos ni recuperarlos si el servidor
   falla.
2. Sin revisión ni CI, los errores llegan a main. La regresión del
   indicador de estado es la prueba.
3. La rama dev se desincroniza de main, porque la documentación se sube
   directo a main y dev no se actualiza.
4. El alcance cambia muy rápido. En un solo día el proyecto pasó de
   "plataforma educativa offline" a "motor generativo 3D" y luego a
   "Amatista 3D Lab". El README sigue describiendo la primera visión.
5. La funcionalidad principal según el README (trabajar sin conexión)
   todavía no tiene código: manifest.json y sw.js están vacíos.

6. RECOMENDACIONES
-----------------------------------------------------------------------------
Proceso (esta semana):
  a. Proteger main en GitHub (Settings -> Branches): exigir PR y que pase
     el CI antes de fusionar.
  b. Crear un workflow de GitHub Actions con "npm ci && npm run lint &&
     npm run build" para el frontend.
  c. Antes de empezar a trabajar: "git checkout dev && git pull origin
     main". O trabajar en ramas cortas creadas desde main.
  d. Subir los documentos también por PR, en docs/ y con nombre
     AAAA-MM-DD_tema.txt.
  e. Que la persona que no escribió el código revise el PR al menos
     5 minutos antes de fusionarlo.

Producto:
  f. Elegir UNA visión (educativa o 3D Lab) y reflejarla en el README.
  g. Definir la meta de la siguiente versión antes de empezar.

Propuesta de meta para v0.2.0:
  [ ] Código del backend en backend/ (main.py, database/, requirements.txt).
  [ ] .env.example con todas las variables reales (DB_PORT, DB_SERVICE).
  [ ] manifest.json y service worker funcionando (PWA instalable).
  [ ] A-Frame instalado con npm y disponible sin conexión.
  [ ] CI con lint y build.
